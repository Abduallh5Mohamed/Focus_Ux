# الخطة الكاملة — 4 مطورين، يومان

## المنتج
PWA: رفع فيديو → اختيار متكلم ظاهر → معالجة → صوت معزول + نص → مقارنة الأصل/المعزول → تنزيل وحذف. تظهر نتيجة الصوت قبل النص إذا تأخر ASR. معالجة GPU على الجهاز/الخادم، وليست داخل PWA أو متاحة أوفلاين.

## ما نعرفه
العزل نجح مبدئيًا على زوج تسجيلات مصري مخلوط صناعيًا: SI-SDRi نحو +17.6 / +8.4 dB. تشغيل دافئ نحو دقيقة لمقطع 14 ثانية، مع 1.7 ثانية تقريبًا للـforward والباقي غالبًا تجهيز الوجه. الأرقام من التقارير وليست ضمانًا لكل فيديو.

الإعداد المرجعي: `detect_every=8, landmark_every=1, downscale=None, window_s=2, merge=direct`. إعداد d16/l2 أضرّ بالهدف B؛ لا يُعتمد افتراضيًا. Falcon وlight والتدريب خارج المسار الحرج.

## نطاق اليوم الأول
- Upload حقيقي حتى 15 ثانية و50MB مبدئيًا، والتحقق على الخادم.
- اختيار وجه حقيقي متصل بالمحرك، وليس ترتيب gallery.
- Jobs + Queue + حالات تقدم حقيقية، وworker طويل العمر.
- مشغل متزامن أصل/معزول، transcript وحالاته، تنزيل وحذف.
- PWA shell، استعادة الطلب بعد refresh، رابط HTTPS يصل له جهاز آخر.
- بدون حسابات أو دفع أو تلخيص أو شات أو نظارات.

## تقسيم الملكية
| المطور | يملك | لا يعدل دون اتفاق |
|---|---|---|
| 1 | `services/worker/`, `packages/ml/` | قاعدة Jobs والـUI |
| 2 | `services/api/`, `infra/`, مخطط DB | ملفات الواجهة وداخل النموذج |
| 3 | صفحات upload/select/process، PWA shell | ResultsPlayer وعقود الخلفية |
| 4 | results/player/transcript، اختبارات التكامل، الإصدار | تحسينات ML |

المشترك `contracts/` يملكه Dev 2 بمراجعة الجميع. إعداد frontend المشترك يملكه Dev 3؛ Dev 4 يملك الدمج والإصدار وليس كل الملفات المشتركة.

## الهيكل المقترح
```text
product/
  apps/web/src/{pages,features,components,lib}
  services/api/
  services/worker/
  packages/ml/
  contracts/
  tests/integration/
  infra/
  .env.example
  README.md
```
الستاك: React + Vite + TypeScript لتصدير static سريع، FastAPI/Python، SQLite على جهاز API، ومجلد ملفات محلي. إذا بدأ الفريق Next.js فعلًا يمكن الاستمرار بشرط static export للواجهة على Pages؛ SSR ليس مطلوبًا.

## عزل الأربعة والتكامل
1. Dev 4 يجهز المستودع الأساسي وcommit أول، Dev 3 يجهز web scaffold وDev 2 يثبت العقد في أول ساعة.
2. أربع branches: `dev/ml`, `dev/api`, `dev/pwa`, `dev/results`، كل شخص checkout مستقل. لا تشغلوا وكلاء كتابة على نفس checkout.
3. كل شخص يملك واجهته، ويبدأ على mocks موحدة عندما ينتظر الطرف الآخر. الموك لا يظهر كمعالجة حقيقية في الإصدار.
4. دمج صغير كل 3 ساعات، مع اختبار smoke بعد الدمج. لا تؤجلوا PR ضخمًا لآخر يوم.
5. تغييرات العقد تمر على أصحاب الواجهات قبل دمجها. لا يعدل أي مطور lockfile بالتزامن مع الآخر.

## تعريف Done
- مستخدم خارجي يرفع ملفًا جديدًا ويختار وجهًا ويستلم الصوت الصحيح ويفهم الانتظار.
- النص جاهز أو له حالة واضحة؛ فشله لا يكسر الصوت.
- التبديل لا يغير موضع التشغيل ولا يشغل الصوتين معًا.
- الملفات لا تختلط بين مستخدمين، الوصول محمي، والحذف فعلي.
- refresh يستعيد الطلب، والواجهة توضح offline، ولا تزعم تشغيل AI دون شبكة.
- نتيجة اختبار GT لكل هدف، قياس end-to-end للنسخة النهائية، وتعليمات إعادة التشغيل.

## أولويات القص عند التأخر
احذفوا تلوين الكلمات، MP4 export، تسجيل الكاميرا، والثيمات المتعددة قبل المساس بالرفع والاختيار والعزل والمقارنة والتنزيل والحذف. real-time هدف محاولة اليوم الثاني وليس شرط تسليم الأساس.
