Conclusion

Measured on CPU, English LibriSpeech read speech (not Egyptian Arabic), 6 two-speaker and 6 three-speaker mixes of about
10 s, oracle region labels, real pretrained weights only. This is a small sample (one mix per condition), so treat the
numbers as a direction, not a precise ranking.

Did any candidate improve over the gated baseline (which mutes every overlap: SI-SDRi about -30 dB, target retention 0)?

2-speaker overlap (rule from COMPARISON_RULE.md applied to the hybrid output):
- REAL-TSE WeSep BSRNN: improves. SI-SDRi +16.1 dB in overlap, target retention 0.94, interferer leakage share ~0 (ratio 0.0),
  STOI 0.91, PESQ 2.87, muted 4 %. Whole-mixture raw extraction is even better (+18.0 dB).
- USEF-TSE: improves by the rule, but only barely in hybrid form (+1.8 dB, retention 0.59, 29 % muted, because the
  voiceprint check rejected many of its 8 kHz outputs). Raw whole-mixture extraction is strong (+12.8 dB, retention 0.94).
- SpEx+: does not improve. Raw +0.4 dB; hybrid -19.8 dB because 80 % of its output was muted by the voiceprint check.

3-speaker mixes (caveat: in the partial mixes some stretches have only the target plus ONE other speaker, and the overlap region includes them; only the 3 full-overlap mixes are pure target + 2, where WeSep hybrid is +2.96 dB, USEF raw +2.3 dB):
- No candidate meets the rule. WeSep gets closest: hybrid SI-SDRi +4.6 dB, retention 0.71, leakage share 7 %, but the
  pooled leakage ratio is 0.96 (limit 0.5), driven mostly by one mix (full overlap, target 6 dB quieter: ratio 4.9,
  SI-SDRi -1.1 dB). Raw WeSep +6.0 dB, USEF +5.0 dB, SpEx+ +5.7 dB, all with 13-19 % of the interferer energy kept.
  Extraction in 3-speaker overlap is therefore partly useful but unreliable, especially when the target is the quietest voice.

Things to know when reading the tables:
- Raw vs hybrid: the hybrid's voiceprint check (the production-shaped safeguard) is what mutes most of the 8 kHz models'
  output. That is a result about the check plus the models' band limit, not only about separation. The raw rows show
  separation alone.
- The pooled "leakage ratio" is a mean of per-mix ratios and is dominated by mixes where little target energy is kept;
  "leakage share" (share of interferer energy kept) is the steadier number.
- Output level and polarity of all three checkpoints had to be fixed by the same least-squares step (rule item 10);
  without it the numbers are not usable.
- 8 kHz models lose everything above 4 kHz, which lowers STOI and PESQ against the 16 kHz reference.
- WeSep is also the slowest to load and, on CPU, runs at about 1.0x real time on a 10 s mix; USEF-TSE about 5x (too slow on CPU);
  SpEx+ about 0.24x. GPU timing and VRAM are not measured here.

Licence-qualified recommendation:
- Technically best: WeSep BSRNN in 2-speaker overlap. Its weights have NO explicit licence ("unclear, not approved for
  deployment"). USEF-TSE is "academic / non-commercial only". Neither is approved for deployment. SpEx+ (Apache-2.0 per the
  model card, "clear for unrestricted use") did not improve over muting, so there is no licence-clean model that helps today.
- Recommended validated model: none approved for deployment. WeSep is validated for research use only.

Smallest production change if the licence is later resolved (proposal only, not built, defaults stay as they are):
use the existing HybridExtractor with the WeSep adapter in place of the gated baseline's muting, behind a default-off
setting, only for regions the diarizer labels as a 2-speaker overlap that includes the target, and keep the voiceprint
check that mutes uncertain output. The experiment used ground-truth region labels, so a real diarizer's overlap detection
is still unmeasured. 3-speaker overlap stays muted.

Most likely next options: (1) ask the REAL-TSE authors for a licence or retrain WeSep BSRNN on licensed data; (2) fine-tune on
Egyptian Arabic mixtures (the checkpoints saw only English); (3) measure on the RTX 3050 with the commands in
RTX3050_COMMANDS.md before relying on any timing.

# Comparison rule (written before any result was read)

Data: LibriSpeech dev-clean (English read speech, CC-BY-4.0). **Not Egyptian Arabic.** Device: CPU.

1. **Same inputs for everyone.** Every candidate and the gated baseline get the same 12 mixtures (6 two-speaker,
   6 three-speaker), the same separate enrollment clip per target, the same oracle region labels, the same
   hybrid settings (4 s windows, 20 ms seams, voiceprint check at the embedder's target threshold) and the same
   seed (`--seed 83`). Nothing is tuned per candidate.
2. **2-speaker and 3-speaker groups are never pooled together.** (The overlap region of a 3-speaker partial mix also contains stretches with the target plus only one other speaker; the group label says so.) Each is ranked on its own.
3. **Ranking uses the overlap region only** (samples where the target and at least one other speaker talk),
   on the *hybrid* output, because that is what FOCUS would run (target solo turns pass through, extraction only
   in overlap). Raw whole-mixture extraction is reported next to it, not ranked.
4. **8 kHz models** (USEF-TSE, SpEx+) get audio resampled 16 -> 8 kHz and their output is resampled back to
   16 kHz before scoring, so all outputs are scored at 16 kHz. Their content above 4 kHz is lost; this bandwidth
   loss is noted in the report and is part of what is measured.
5. **Muted output counts as -30 dB SI-SDR** (clamp [-30, 50] dB), so the gated baseline's SI-SDRi in overlap is about
   -30 dB by construction. Beating it on SI-SDRi alone therefore proves nothing. A candidate counts as
   **improving** over the gated baseline in a group only if, pooled over that group's overlap regions, all of:
   * SI-SDRi is at least +1 dB (better than leaving the mixture untouched, hence also better than the baseline);
   * target retention is at least 0.30 (share of the target reference energy kept);
   * interferer leakage ratio (interferer energy kept / target energy kept) is at most 0.50.
   Otherwise the group's result for that candidate is "does not improve", and the gated baseline stays.
6. **Ranking among improving candidates**: highest pooled overlap SI-SDRi. Mean over mixes (each mix weighs the same).
7. **Reported but not used for ranking**: STOI and PESQ (wideband) against the clean target reference in the
   overlap region, muted share, CPU processing time, real-time factor, whole-clip scores.
8. **Only real pretrained weights.** A candidate that fails to load or run is reported as failed with the exact
   error and is excluded from the numbers; no stub, oracle or fake extractor appears.
9. **Licence gate.** A candidate with unclear or non-commercial weights is never described as approved for
   deployment, even if it wins.
10. **Polarity and level.** The three checkpoints are trained with scale-invariant losses, so their output level and
    polarity are arbitrary (seen in a one-mix smoke test: SpEx+ peaks of ~1e5, USEF-TSE inverted and about 3x too loud).
    The same step is applied to all three: each extracted window is multiplied by <est, mixture> / <est, est>,
    which uses only the mixture, never a reference. Without it the hybrid output is not usable. Retention is therefore
    a measure of how much of the target is present after this common convention.

# Repeat on the Windows laptop (RTX 3050) for GPU timing and peak VRAM

The laptop could not be reached from the Replit workspace, so **nothing in this experiment was measured on the RTX 3050**.
Every timing in `report.html` is CPU (8 cores, no GPU). Peak VRAM there says "not measured (CPU)".

Run from the repository root in a Command Prompt. `PY` is the original environment's Python (it already holds the GPU torch).

```bat
set PY=A:\focus\.venv\Scripts\python.exe

REM 1. Setup (approval-first; separate folder %LOCALAPPDATA%\FocusVoice\overlap; downloads ~1.5 GB)
product\tools\Setup-Overlap.cmd
REM    Answer yes. If the optional pyannote step fails, that does not affect these three candidates.
REM    Scoring packages for this experiment (STOI and PESQ), installed into the same separate folder:
%PY% -m pip install --target "%LOCALAPPDATA%\FocusVoice\overlap\site" pystoi pesq setuptools
REM    (pesq compiles C code; without a C compiler it fails and the report prints PESQ as an error, STOI still works.)
%PY% product\tools\overlap_experiment.py readiness --out experiment-out

REM 2. Solo recordings and the mixture set (same data, same seed 83 as the CPU run)
curl -L -o dev-clean.tar.gz https://www.openslr.org/resources/12/dev-clean.tar.gz
%PY% product\tools\librispeech_solo.py --archive dev-clean.tar.gz --out solo --speakers 84 1462 1673 1919 174 251 422 652 --seconds 60
%PY% product\tools\overlap_set.py --solo-dir solo --out overlap-set --language english_librispeech_non_egyptian --layout experiment --seed 83

REM 3. Comparison run: same candidates, same mixes, GPU
%PY% product\tools\overlap_experiment.py run --set overlap-set --out experiment-out --device cuda --candidates wesep_bsrnn usef_tse spexplus --seed 83
%PY% product\tools\overlap_experiment.py render --out experiment-out
```

`experiment-out\report.html` has the same tables with GPU seconds, real-time factor and peak VRAM. The separation scores
should match the CPU run closely (fp16 on GPU can move them slightly; the run falls back to fp32 on NaN).
If a candidate fails to load, the report shows its exact error and the others still run.
